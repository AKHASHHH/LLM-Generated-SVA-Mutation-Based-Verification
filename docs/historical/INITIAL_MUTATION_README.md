# Project 4 v2: mutation-based evaluation of LLM-generated SVA (APB timer)

This package measures how well two independently generated SVA checker sets (GPT `sva_gpt_1.sv`, Sonnet `sva_claude_1.sv`) detect **10 controlled single-defect mutants** of an APB timer specified by the frozen APBTMR-SPEC v1.0. It runs on Synopsys VCS, with VCD or FSDB waveforms for Verdi.

**What is what**

| Item | Origin | Status |
|---|---|---|
| `$GEN_DIR/rtl_*.sv`, `$GEN_DIR/sva_*.sv` | GPT-6 / Claude Sonnet, isolated sessions | **Original artifacts.** Read-only; SHA-256 checked before every run (`docs/gen_sha256.txt`). |
| `ref/apb_timer_ref.sv` | **Opus-assisted reference** (Claude Opus) | Not an independent golden model. Evidence: matches the spec model on every vector, and is formally equivalent to all 4 generated RTLs (`evidence/ref_equivalence/`). |
| `mutants/M01..M10` | Generated by `scripts/make_mutants.py` | **Controlled, intentional defects.** Never report them as natural bugs. |
| `vectors/all.vec` | `scripts/gen_vectors.py` + `scripts/specmodel.py` (spec model, Opus) | 81 tests / 8,348 cycles: the 23 spec examples, 18 directed coincidence/boundary tests, and 40 short seeded-random tests (seed 20261015). |
| `tb/tb_top.sv`, `scripts/` | Opus | Testbench and automation. |

## 1. Install into Project_4/v2 (tcsh)

The package expects the six original files in `Project_4/v2/gen/`. If they are elsewhere, set `GEN_DIR`.

```
cd ~/Project_4/v2 && tar xzf apbtmr_v2_mutation.tar.gz && cd mutation
setenv GEN_DIR ~/Project_4/v2/gen
./scripts/run_ref_check.sh
```

Nothing under `$GEN_DIR` is ever written. Every script that reads the originals checks them first with `sha256sum -c docs/gen_sha256.txt` and stops on any mismatch.

## 2. Run (one line per step, from the `mutation/` directory)

| Step | Command | What it establishes | Pass/fail evidence |
|---|---|---|---|
| 1 | `./scripts/run_ref_check.sh` | Reference correctness against the spec examples and all vectors (outputs + 10 state elements every cycle) | `results/ref_check/summary.txt` must show `ref: PASS` (0 spec mismatches) |
| 1b (optional) | `./scripts/run_ref_check.sh all` | The same check on the 4 original generated RTLs | Same file. A mismatch here would be a natural RTL bug candidate. |
| 2 | `./scripts/run_sva_compile.sh` | First-pass compile of each original SVA with the reference DUT | `results/compile/status.tsv`; first-pass logs kept as `results/compile/*.first_pass.log` |
| 3 | `./scripts/run_sva_fp.sh` | False positives: each SVA on the reference | `results/fp/*.log`, `results/fp_summary.md` |
| 3b (optional) | `./scripts/run_sva_fp.sh all` | The same, also on the 4 generated RTLs | `results/fp/sva_*.rtl_*.log` |
| 4 | `./scripts/run_activation.sh` | Each mutant is activated (diverges from the reference), with no SVA | `results/activation/*.log` |
| 5 | `./scripts/run_detection.sh` | Each SVA set × each mutant | `results/detection/sva_*/*.log` |
| 6 | `python3 scripts/make_matrix.py` | Combines everything into the matrix | `results/matrix.md`, `results/matrix.csv` |
| all | `./scripts/run_all.sh` | Steps 1–6; stops if step 1 fails | as above |

Expect about 25 VCS compiles in total. If your site's VCS needs different options, override them with `setenv VCS_OPTS "..."` and `setenv SVA_OPTS "..."`. The defaults are `-full64 -sverilog -timescale=1ns/1ps -debug_access+all -kdb`, plus `-assert svaext` for SVA builds.

## 3. Outcome classes (never merged)

| Outcome | Meaning |
|---|---|
| COMPILE_FAIL | The original SVA did not compile. Recorded per SVA set; the first-pass log is preserved. |
| False positive | An SVA failure on the **reference** run. Adjudicate it (section 5). |
| NOT_ACTIVATED | The mutant never diverged from the reference. Excluded from the kill rate and **not** a miss. |
| DETECTED | The mutant was activated, and the SVA run has at least one failure (label, time) **absent from the reference run** with identical vectors. |
| MISSED | The mutant was activated and there is no such new failure. Adjudicate it before reporting. |
| RUN_ERROR | A log is missing or the simulation did not reach `TBSUMMARY`. |

The first time you run `make_matrix.py`, look at the "[parser] … raw failure lines" it prints. They confirm that your VCS assertion-failure messages are being recognised (the parser keys on the hierarchical path `u_sva.` plus `failed` or `Error`). If a log clearly contains SVA failures and the parser reports 0, send me two of those lines and I'll adjust the regular expression.

## 4. Waveforms for Verdi

Builds are named `chk_ref`, `sva_gpt_ref`, `sva_claude_ref`, `act_<Mxx_name>`, `det_gpt_<Mxx_name>` and `det_claude_<Mxx_name>`.

```
./scripts/waves.sh det_gpt_M03_RELOAD_USES_WRITTEN_LOAD
vcd2fsdb results/waves/det_gpt_M03_RELOAD_USES_WRITTEN_LOAD.vcd -o results/waves/det_gpt_M03.fsdb
verdi -dbdir build/det_gpt_M03_RELOAD_USES_WRITTEN_LOAD/simv.daidir -ssf results/waves/det_gpt_M03.fsdb &
```

To dump FSDB directly, use `./scripts/waves.sh <build> fsdb` (needs `VERDI_HOME`). It rebuilds with `+define+FSDB` and the Verdi PLI (`setenv FSDB_OPTS ""` if your VCS already links Verdi).

Useful signals:
* `tb_top.d_*` (DUT state) against `tb_top.ref_i.*` (reference state);
* `tb_top.dut.PRDATA` / `irq`;
* `tb_top.u_sva.*` (assertions).

The testbench prints `TBTEST tid=… time=…` at each test start; test names are in `vectors/tests.idx`. For each mutant, the first divergence time is in its `TBSUMMARY` line.

## 5. Adjudication rules

**A false positive (SVA failure on the reference):**
1. Rule out the harness: hierarchical binding, timescale, time-0 reset (see `docs/SVA_INTEGRATION_REVIEW.md` §3). Harness problems are fixed in the harness, never in the SVA.
2. Open the failing time in Verdi. Write down the spec rule the assertion claims to check, and derive the expected values cycle by cycle from the spec text.
3. If the spec text agrees with the reference, it is a **natural defect in the generated SVA** (a reportable finding). Cite the R-ID, the assertion label and the failing cycle.
4. If the spec text agrees with the assertion, stop. That would be a reference / spec-model / generated-RTL common-mode issue.

**A miss (activated mutant, no new failure):**
1. Confirm activation in `results/activation/<id>.log`, including the first divergence.
2. Identify the assertions that should catch it: the requirement in `docs/MUTANTS.md` matched to the assertion labels in the SVA file.
3. Check whether those assertions' antecedents were true in the divergence window (Verdi). If they never fired, the miss is a **stimulus/vacuity** limitation, not an SVA weakness. Say so.
4. Otherwise classify it: *no property covers the rule* / *property present but too weak* / *property present but wrong*.

Optional assertion coverage, to support vacuity statements. The syntax depends on your VCS version:

```
setenv SVA_OPTS "-assert svaext -cm assert"
./scripts/run_sva_compile.sh
cd build/sva_claude_ref && ./simv +VEC=../../vectors/all.vec -cm assert && urg -dir simv.vdb -format text && cd ../..
```

**A compile failure:** follow `sva_corrected/README.md`.

## 6. What has and has not been verified before delivery

Verified here, without VCS (details in `evidence/` and `docs/`):
* **slang 12.0** elaborates the testbench with: the reference; each of the 10 mutants; each of the 4 generated RTLs; and each original SVA file. Result: 0 errors and 0 warnings. FSDB tasks are excluded, since they need Verdi.
* **Yosys k-induction** proves the reference equivalent to all 4 generated RTLs (outputs + state, unconstrained inputs, both reset models).
* **A local CXXRTL simulation** of the reference matches the spec-model expected values on all 8,348 cycles. In the same simulation all 10 mutants are activated: they diverge from the expected values. See `evidence/local_precheck/RESULTS.md`.
* **`make_matrix.py`** classifies every outcome class correctly on synthetic logs.

**Not verified:**
* VCS compilation;
* any SVA behavior (pass, fail, detection);
* the exact VCS message format the parser relies on.

No mutant has been detected or missed yet. That is only established by steps 5–6 in VCS.
